# Coding standards

Read this file and `docs/architecture.md` before you write or review code, and review finished code against them before you call the work done. The rules for one area live in that area's file, and the route table in `AGENTS.md` says which files cover the paths you change: read each one before you change those paths. Read [errors.md](errors.md) before you add or change an error, and [observability.md](observability.md) before you add a recorded number, a log line or a profile counter.

Every rule names its check. A lint rule or a `pnpm` script enforces it, or `judgment` marks it for reviewers. `pnpm check:rules` fails when a named check is not an enabled lint rule or a `package.json` script. It also fails when a `rushline/` or `anti-slop/` rule enabled in `oxlint.config.ts` is not named in a rule doc that `AGENTS.md` routes. `pnpm check:rule-routes` fails when a rule table sits in a file `AGENTS.md` does not route, a `check:` script has no row, or a doc's rule row count differs from `scripts/rule-rows.json`. A new rule ships with its row, in the file for the paths it covers. No rule has an exemption: there are no allowlists, baselines, or per-file disables, and code that breaks a rule is fixed. The ledger enforces that too. It works out each rule's setting the way oxlint does, preset rules first, then the root rules, then each override in order, and fails when `oxlint.config.ts` sets any rule below `error` in its root rules or in an override, or when a preset override turns off a rule that is otherwise on and no later override for the same files turns it back on. The Ultracite presets turn off `no-empty-function` and `promise/prefer-await-to-then` for test files, so `oxlint.config.ts` turns both back on there. A rule the presets leave off is not part of the standard.

## The checks

Every change is held to these standards and the area files `AGENTS.md` routes it to, and passes `pnpm verify`. [standards/tooling.md](standards/tooling.md#the-checks) says what `pnpm check`, `pnpm verify` and CI run, in order.

| Rule | Check | Scope | Exemption |
| --- | --- | --- | --- |
| Run `pnpm check` and `pnpm build` after source changes. | `pnpm verify` | Repository | None |
| Code is formatted by oxfmt. | `pnpm format:check` | Repository | None |
| Repository code is TypeScript. No tracked or new `.js`, `.mjs`, `.cjs` or `.jsx` file exists. | `pnpm check:typescript-only` | Repository | None |
| Game art is not committed. No tracked or new model, image, sound, video or font file (`.glb`, `.gltf`, `.webp`, `.png`, `.jpg`, `.avif`, `.ktx2`, `.blend`, `.mp3`, `.ogg`, `.wav`, `.mp4`, `.woff2` and the rest of the list in `scripts/check-art.ts`) exists outside `docs/`. Art lives in the R2 bucket under a content-addressed key, and `apps/web/src/assets/art.json` maps each name to its key, which must be a content hash with the name's extension. `pnpm art:stage` writes it. | `pnpm check:art` | Repository | None |
| Types check in the root project and every workspace. The checker is tsrs, the Rust port of the TypeScript 7 compiler, pinned to an exact version. | `pnpm typecheck` | Repository | None |
| Look at the running game after any change to `apps/web/src/game` or to handling. Passing tests do not show that it plays well. | judgment | `apps/web/src/game`, `packages/sim` | None |
| Every change lands with the way its author proved it works: a test, a script in `tools/`, or a feature file in `.claude/skills/verify-rushline/features`. A new subsystem, such as the server, a multiplayer room, sign-in, or the store, ships with its own way to verify it, so the next agent can check it without asking. | judgment | Repository | None |
| Every `git ls-files` call passes `-z`, and its output is split on NUL with each path's whitespace kept, never split on newlines or trimmed. Without `-z` Git quotes a path with non-ASCII characters, quotes or tabs, and a check that opens the quoted text silently skips the file. The checks in `scripts/` list files only through `repositoryFiles` in `scripts/git-files.ts`. The rule reports every array literal whose first element is `"ls-files"` and that has no `-z`, or short-option group containing `z` such as `-coz`, before `--`. It walks the arguments the way Git does, so a value taken by `-x`, `-X`, `--exclude`, `--exclude-from`, `--exclude-per-directory`, `--format` or `--with-tree` is not an option, and neither is anything after `x` or `X` in a group. It does not follow the output to its parsing. | `rushline/require-nul-file-list` | Repository | None |

## Keep each module to its job

| Rule | Check | Scope | Exemption |
| --- | --- | --- | --- |
| `alchemy.run.ts` is the Alchemy composition root. `apps/` holds deployable Cloudflare apps, `packages/` holds shared code, `tools/` holds repository automation, `scripts/` holds the checks, and `docs/` the docs. No other top-level folder exists, apart from dot folders. Every folder under `apps/`, `packages/` and `tools/` is a pnpm workspace with its own `package.json`, and `pnpm-workspace.yaml` matches each of them and nothing else. | `pnpm check:roots` | Repository | None |
| No relative import leaves its workspace. A workspace is the folder of the nearest `package.json`. Code another workspace uses is imported by its package name, such as `@racer/telemetry/jsonl-store`, and every workspace declares each package it imports in its own `package.json`, including `@racer/*` workspaces and packages the root already declares. `node:` and `cloudflare:` runtime builtins and the workspace's own name need no declaration. Unused declarations are covered by the `pnpm check:dead` row. | `rushline/workspace-imports` | Repository | None |
| Every TS, TSX, CSS and SQL source file is at most 20,000 JavaScript string characters, counted as `readFileSync(file, "utf-8").length`; 20,000 passes and 20,001 fails. Split a larger file by what its parts own, and keep new files well under the limit. The check reads every tracked file and every untracked file Git does not ignore, so build output and other ignored files are not counted. | `pnpm check:size` | Tracked and non-ignored untracked source, repository-wide | None |
| Every TS, TSX, CSS and SQL source file under `apps/`, `packages/`, `tools/` and `scripts/` belongs to exactly one entry in `scripts/features.ts`; two entries whose patterns match the same file is an error, with no precedence between them. Each entry's start files are files it owns, and its docs links, verify recipes and perf ids resolve. `docs/feature-map.md` is regenerated from the manifest with `pnpm feature-map` and never edited by hand. | `pnpm check:feature-map` | Tracked and non-ignored untracked source under `apps/`, `packages/`, `tools/` and `scripts/`; `scripts/*features.ts`; `docs/feature-map.md` | None |
| No file, export, type or dependency is left unused. An export used only in its own file loses `export`. Delete the rest, and the docs that describe it. knip checks every workspace, and checks the exports of `packages/*` too, although each of their files is a package entry. `knip.json` ignores no file or export; its one ignore option is `ignoreDependencies: ["cloudflare"]` for `apps/web`. | `pnpm check:dead` | Repository | None |
| `packages/sim` owns every game rule. If the game should behave differently, change `packages/sim`. | judgment | `packages/sim` | None |
| `packages/track` owns the track format, compilation and track data. The simulation and the renderer both read the compiled `Track`. | judgment | `packages/track` | None |
| `packages/career` owns every career rule: money, tiers, the shop, the field draw, rival memory, settlement and the save format. React renders it and never changes a rule. | judgment | `packages/career` | None |
| `apps/web/src/game` owns rendering, audio, input and the frame loop. It reads simulation state and never changes a rule. | judgment | `apps/web/src/game` | None |
| React renders menus and the HUD, does no per-frame work, and loads the game module with a dynamic import. | judgment | `apps/web/src/components`, `apps/web/src/routes` | None |
| `packages/ui` owns the shadcn components and global styles. | judgment | `packages/ui` | None |
| No module outside the word-mixing modules the rule lists uses a bitwise operator. `&`, `^`, `~`, the shifts and bitwise or coerce their operands to 32-bit integers, so a wrong number comes back quietly instead of failing, and a double that no longer fits is truncated. A hash needs them: `packages/sim/src/snapshot-hash.ts` is MurmurHash3 x86 128 word for word, and is the one file on the list. It takes no exemption and no directive; the list is the rule's option, so adding a file to it is a change to the rule with a reason in this row. | `rushline/no-bitwise` | `wordMixingFiles` in `oxlint.config.ts` | None |
| No static value import from React reaches `apps/web/src/game` or the `three` package; React imports their types with `import type` and loads the game through the literal dynamic imports in `apps/web/src/asset-load.ts`. The check starts at every `apps/web/src/**/*.tsx` file, resolves each import with the client build's Vite resolver, and follows value imports, value re-exports, side-effect imports and CommonJS `require` through every module, first-party or installed, before tree shaking. It judges a module by its real path, or by the package that owns it, and prints the chain of imports, with line numbers, to each crossing. An import it cannot resolve, a file it cannot parse, or a dynamic import of a computed specifier is an error. | `pnpm check:renderer-imports` | `apps/web/src/**/*.tsx` and every module they import statically | None |

## Use Effect only at the edges

| Rule | Check | Scope | Exemption |
| --- | --- | --- | --- |
| Effect runs at network, storage, process and error boundaries: the art tools in `tools/art` and the art route's `apps/web/src/server/art.ts`, the race room's Worker in `apps/rooms` and its tool `tools/rooms`, whose tick loop and seats in `host.ts` stay plain functions, the telemetry server, `packages/telemetry`, the browser's telemetry delivery (`apps/web/src/diagnostics/upload` and `uploader-runtime.ts`, loaded on demand), `packages/devtools` (launching the browser and its desktop session, the CDP client and trace analysis, which `tools/perf` and `tools/verify` share), `tools/perf`, `tools/verify`, `tools/madrid`, `tools/road-test`, the Madrid corridor codec in `packages/track/src/madrid-schema.ts` and `madrid-corridor.ts`, the career save codec, the browser save (`apps/web/src/career/save.ts` and its storage modules) and the game's model downloads (`apps/web/src/asset-runtime.ts` and `apps/web/src/assets`, loaded on demand). The simulation, track, career rules, renderer and React are plain functions. | judgment | Repository | None |
| Import Effect by module path, such as `effect/Effect` or `effect/Schema`, never from the `effect` root. | `no-restricted-imports` | Repository | None |
| Every promise is awaited, returned, or explicitly discarded with `void`. | `typescript/no-floating-promises` | Repository | None |
| Code that waits for a worker or child process to exit reads the exit code and fails when it is not 0. A worker can finish its writes and still exit 1, so a test that only waits passes when every worker fails. The rule reports a call to `once` from `node:events`, under any import name or as `.once` on its namespace or default import, whose second argument is the literal `"exit"` and whose result is discarded: the call, optional or not, or its `await` is a statement or is under `void`. It does not check the receiver's type or what is done with a bound result. | `rushline/no-discarded-exit` | Repository, tests included | None |
| A value typed `any`, such as the result of `JSON.parse`, is decoded or typed before typed code reads, calls, passes or returns it. | `typescript/no-unsafe-assignment`, `typescript/no-unsafe-argument`, `typescript/no-unsafe-call`, `typescript/no-unsafe-member-access`, `typescript/no-unsafe-return` | Repository | None |

The inherited Ultracite presets run with type information (`options: { typeAware: true }`), so every type-aware rule they turn on is enforced too, such as `typescript/strict-boolean-expressions` and `typescript/no-confusing-void-expression`. Every other rule they turn on is enforced in every file as well, such as `func-style` (functions are `const` arrow functions), `no-use-before-define`, `no-shadow`, `no-nested-ternary` and `promise/prefer-await-to-then`. Only the rules above are listed, because they state Rushline's own decisions.

[standards/effect.md](standards/effect.md) holds the rules for the files inside the Effect boundary.

## Keep types honest

| Rule | Check | Scope | Exemption |
| --- | --- | --- | --- |
| No type assertion without a nearby `SAFETY:` note that says why the assertion holds. `as const` needs none. | `anti-slop/require-safety-comment-for-type-assertion` | Repository | None |
| A `SAFETY:` note ends with a `Verified by: <test title>` line, and a test with that exact `it` or `test` title exists under `apps/`, `packages/` or `tools/`. This is a separate rule, not an extension of the vendored anti-slop rule, so the vendored plugin stays a copy. | `rushline/safety-verified-by` | Repository | None |
| No chained assertions such as `value as unknown as User`. | `anti-slop/no-chained-type-assertions` | Repository | None |
| Do not widen a known value to a broad type and then assert it back to a narrower one. | `anti-slop/no-widen-then-assert` | Repository | None |
| Do not pass a value whose type is already known into a broad or anonymous target type that throws the evidence away. | `anti-slop/no-known-value-widening` | Repository | None |
| No dictionary type whose value is `unknown`, `any`, `object` or `{}`. | `anti-slop/no-unsafe-dictionary-type` | Repository | None |
| No `unknown` parameter except `cause`, no function that returns `unknown`, and no type alias that resolves to `unknown`. Decode unknown input at its I/O boundary. | `anti-slop/no-unknown-parameters`, `anti-slop/no-unknown-returns`, `anti-slop/no-unknown-type-aliases` | Repository | None |
| No parameter typed `object`. Name the type the function needs and parse input into it at its boundary. | `anti-slop/no-object-parameters` | Repository | None |
| No runtime `typeof` checks. External values are decoded into domain types at the boundary. | `anti-slop/no-runtime-typeof` | Repository | None |
| No `Reflect.get` or `Reflect.apply`. Use typed property access and direct calls. | `anti-slop/no-reflect-get`, `anti-slop/no-reflect-apply` | Repository | None |
| No conditional spread of an empty object to omit a field. | `anti-slop/no-conditional-empty-object-spread` | Repository | None |
| No symbol name contains `shape`. Name the thing the value is. | `anti-slop/no-shape-in-symbol-names` | Repository | None |
| A finite set of values is written once, as an `as const` tuple in the module that owns it. Its union is `(typeof values)[number]`, and a schema for it is built from the same tuple, as `weaponKinds` in `packages/sim/src/state.ts` feeds both `WeaponKind` and the save's `Weapon` schema. A deliberate subset of a domain, such as the rivals in `defaultSetup`, keeps its `readonly T[]` annotation. | judgment | Repository | None |
| A rider is named by its `RiderId`, never by its place in an array. `createRace` gives each rider its id once, from `rosterOf(setup)`, the player first, then the rivals in setup order, then the police, and `RaceState.riders` keeps that order for the whole race. A reference from one rider to another, such as a grudge, a chase, `lastHitBy` or an event's rider, is a `RiderId`, and a missing one is `null`. `riderOf(list, id)` reads a rider's entry from `riders` or from any list kept one entry per rider, without allocating. A rider array is indexed only by the counter of the `for` loop walking it. That counter may index arrays, offsets included, and may go to a function declared in the same module, but it is never returned, stored or handed to another module. A rider array is never destructured by place and never read with `at`, `slice`, `indexOf`, `findIndex`, `entries`, `keys` or another method that works by place. A callback passed to its array methods is an inline function or one declared in the same module, and it takes no index. In a module that handles sim riders, a rider reference is compared with a `RiderId` such as `PLAYER_RIDER` or `rider.id`, never with a number. The brand keeps a plain number out of every `RiderId` parameter. The rule finds rider arrays by the name `riders`, so whether a list under another name holds riders is for review. | `rushline/rider-by-id`, judgment | Repository | None |
| An operation that must decide what every variant of a union means, such as `boardNote`, `weaponMesh` or a rival memory's bonus, is an exhaustive `switch` with no catch-all default. Every variant has its own `case`, including the ones that do nothing or give zero, and the `default` that `default-case` asks for returns the narrowed value `satisfies never`. A new variant is then a type error and a `typescript/switch-exhaustiveness-check` error until it has a case. A handler that reacts to only some variants, such as a sound for some race events, is not such an operation. | `typescript/switch-exhaustiveness-check`, judgment | Repository | None |

## Write no comments

| Rule | Check | Scope | Exemption |
| --- | --- | --- | --- |
| No comments in `.ts`, `.tsx`, `.js` or `.mjs` files. Names, types and small functions carry the meaning; design rationale goes in `docs/` or the commit message. The comments allowed are tool directives: `oxlint-disable…`, `eslint-disable…`, `oxlint-enable` and `eslint-enable` lint directives, `@ts-expect-error`, a `SAFETY:` note and the line comments that continue it, `/// <reference …>`, `@vite-ignore`, `#__PURE__` and `@__PURE__` annotations, and a shebang. | `rushline/no-comments` | Repository | None |
| Every lint suppression and `@ts-expect-error` says why after `--`. `@ts-ignore` and `@ts-nocheck` are banned. Prefer code that needs no directive. | `rushline/require-suppression-reason` | Repository | None |
| No comments in CSS. The check tokenizes each CSS file with PostCSS, so a `/*` inside a string or a `url()` is not a comment. | `pnpm check:css-comments` | `*.css` | None |

## Test what a player would notice

| Rule | Check | Scope | Exemption |
| --- | --- | --- | --- |
| Do not mock modules. Replace a dependency through a real interface. | `anti-slop/no-module-mocking` | Repository | None |
| A test that guards against a regression fails when the old defect is put back in the layer where it lived. If the fix was in a controller, the test drives the controller, not the writer it calls. When several causes can produce the same outcome, the test asserts the fact that tells them apart, such as an on-road landing, a completed tick count or the exact typed error. | judgment | Repository | None |
| Tests pass. | `pnpm test` | Repository | None |
