# Web app standards

Rules for the React app in `apps/web/src` outside `game/`, and for `packages/ui`. The core rules in [coding-standards.md](../coding-standards.md) apply too.

## Keep each module to its job

| Rule | Check | Scope | Exemption |
| --- | --- | --- | --- |
| The handoff from preparing a race to riding it is decided in the transition tables in `apps/web/src/race-handoff.ts` and `apps/web/src/room-handoff.ts`. `SoloDoor` and `SeatedLobby` run the effects those tables return and keep no flag or ref of their own that says how far the handoff has got. A timer they start belongs to an effect that clears it, and that cleanup sends the table no event, because React re-runs effect cleanups in a development build. | judgment | `apps/web/src/race-handoff.ts`, `apps/web/src/room-handoff.ts`, `apps/web/src/components/solo-door.tsx`, `apps/web/src/components/room-lobby.tsx` | None |
| Which screen the app shows is decided in `stepNavigation` in `apps/web/src/navigation.ts`, which takes an event and returns the next `View` and at most one effect. `useFlow` runs the effects and `GameShell` sends events; neither holds a flag or ref that says what screen or race stage the app is in. A race's stage lives in its `View` with the report it carries. The race session, the handoffs and the save stay in their own machines, and navigation learns about them through events. | judgment | `apps/web/src/navigation.ts`, `apps/web/src/components/use-flow.ts`, `apps/web/src/components/game-shell.tsx` | None |
| After the first page load nothing loads the page again to change screens. A screen move is an event to `stepNavigation`, and the address follows the view in place through `showAddress` in `apps/web/src/components/room-url.ts`, which calls `history.replaceState`. The rule reports `location.assign`, `location.replace`, an assignment to `location` or to its `href`, `search`, `pathname`, `hash`, `host`, `hostname`, `port` or `protocol`, `history.pushState`, whose entry no screen would answer, and a variable that holds `location` itself, because a page load through another name would get past the rule. `location.reload()` stays allowed: the Reload and Try again buttons after a failed boot, a newer build or a career held in another tab need fresh code or a fresh save hold, and the player chose them. Until November 10, 2026 every room move loaded `/?room=<id>` again and flashed the loading wordmark between screens. | `rushline/no-page-move` | `apps/web/src` | None |

## Write player text in the game's voice

| Rule | Check | Scope | Exemption |
| --- | --- | --- | --- |
| Player text never says AI, and uses no em dash and no middle dot as a separator. The other riders are street riders, and a rider the room rides for after a drop looks like anyone else, so no screen marks them. Separate parts with a comma or plain words. The owner set this on November 6, 2026, after the rejoin screens and again after the queue screen said `labelled AI`. The rule reads the text a player sees: JSX text and JSX attribute strings with their HTML entities decoded, and string literals and template text with their escapes decoded. It cannot judge tone or jargon, such as `server` or `Catch-up`; review checks those against the street-crew voice. | `rushline/player-copy` | `apps/web/src/components/**`, `apps/web/src/routes/**/*.tsx`, `apps/web/src/career/copy.ts`, `apps/web/src/game/hud.ts`, `apps/web/src/game/race-feedback.ts`, `apps/web/src/game/bar-signs.ts` | None |
