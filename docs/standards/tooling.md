# Tooling standards

Rules for `scripts/`, `tools/oxlint`, `.github/`, `oxlint.config.ts`, `package.json` and the rule docs. The core rules in [coding-standards.md](../coding-standards.md) apply too.

## The checks

`pnpm check` runs the `check` group of `scripts/verify.ts`: formatting, lint, the lint rule tests, this ledger, the rule routes, CSS comments, the TypeScript-only check, the repository roots, the GitHub Action pins, the game art, the renderer imports, source size, the feature map, the save format, dead code, the Madrid stretches, the handling limits, the perf budgets, types, and tests, in that order, and prints how long each took. `pnpm verify` runs the same group, then the build, then the perf gate, `pnpm perf`. Add `--format json` (`node scripts/verify.ts check --format json`) for one JSON report with each check's command, exit code, duration and the tail of its output when it failed. `node scripts/verify.ts static` runs the group without the tests. CI runs four jobs side by side, once for each pull request update and once for each push to `main`. The `static` job runs `node scripts/verify.ts static` and then `pnpm build` as separate steps, so the Actions page shows which of the two failed without opening the log. The `tests` job runs twice. `tests (police)` runs the police balance test, `pnpm test --project police`, on a runner of its own, because its 200 races fill every core. `tests (!police)` runs every other test, so the two together run what `pnpm test` runs. The `replay` job runs `pnpm replay:engines` once for each browser engine, as `replay (<engine>)`. The `perf` job runs `pnpm perf`. Nothing in CI runs `pnpm perf:gpu`, which needs a real GPU, this Mac's or vimaan's; [observability.md](../observability.md) lists what each perf command checks.

| Rule | Check | Scope | Exemption |
| --- | --- | --- | --- |
| Every `uses:` under `.github/` names a local action (`./…`) or pins a full 40-character commit SHA followed by a comment naming the version it points to, as in `uses: actions/checkout@11d5960a326750d5838078e36cf38b85af677262 # v4.4.0`. A tag or branch can be moved to new code after we read it; a commit cannot. To update an action, look up the new release's commit and change the SHA and the comment together. | `pnpm check:action-pins` | `.github/` | None |
| Every `git ls-files` call passes `-z`, and its output is split on NUL with each path's whitespace kept, never split on newlines or trimmed. Without `-z` Git quotes a path with non-ASCII characters, quotes or tabs, and a check that opens the quoted text silently skips the file. The checks in `scripts/` list files only through `repositoryFiles` in `scripts/git-files.ts`. The rule reports every array literal whose first element is `"ls-files"` and that has no `-z`, or short-option group containing `z` such as `-coz`, before `--`. It walks the arguments the way Git does, so a value taken by `-x`, `-X`, `--exclude`, `--exclude-from`, `--exclude-per-directory`, `--format` or `--with-tree` is not an option, and neither is anything after `x` or `X` in a group. It does not follow the output to its parsing. | `rushline/require-nul-file-list` | Repository | None |
| Every lint plugin rule has valid and invalid cases, and the suite fails when a registered `rushline/` or `anti-slop/` rule has none. The same suite runs the ledger's regression cases in `scripts/rule-ledger.test.ts`. | `pnpm lint:rules` | `tools/oxlint`, `scripts` | None |
| Every rule in these docs names its check, every enabled project rule has a row, and `oxlint.config.ts` turns no rule off or below `error` anywhere it applies. | `pnpm check:rules` | Every rule doc `AGENTS.md` routes, `oxlint.config.ts` | None |
| Every rule table sits in a doc that the route table in `AGENTS.md` names, so no rule is orphaned where no agent is sent to read it. Each routed doc exists and holds at least one rule row, each routed path pattern matches a tracked file, and every `check:` script in `package.json` is named by a rule row, so dropping a checked rule's row fails. A doc moves or splits by changing its route in the same change. | `pnpm check:rule-routes` | `AGENTS.md`, every rule doc it routes, `package.json` | None |
