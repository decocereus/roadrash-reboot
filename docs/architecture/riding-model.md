# Riding model

`packages/sim` owns every rule. It has no DOM, Three.js, clock, or unseeded randomness, so the same inputs always produce the same race. State is plain data that `stepRace` advances by exactly 1/60 second. `rushline/deterministic-core` holds the simulation, the track package and the career rules to that: they import only each other and read no clock, entropy, host or loader.

Each race keeps everything that carries over from one tick to the next in `RaceState`. Every rider has a `controller`, `human` or `pilot`, set when the race is built, and an `input`, the six controls it rides on this tick. `stepRace(state, track, frame)` takes an `InputFrame` of two maps keyed by `RiderId`: `handovers`, the riders whose controller changes this tick and the controller each moves to, and `controls`, one `Control` for exactly each rider a human rides once those handovers are made. It checks the frame first and throws when a handover names the controller the rider already has, when a human rider has no control, when a pilot rider has one, or when the frame names a rider the race does not have, so a bad frame changes nothing. Then it makes the handovers, decodes each human's control into that rider's input and plans every pilot rider into its own, in rider order, before it clears the last tick's events. A handover is tick data like a control, so a room that records both replays the race exactly, and a rider handed to the pilot rides on under the same plan a rival gets. `?autopilot` is the player's rider built with the `pilot` controller, the same path as a rival's. `packages/sim/package.json` closes `@racer/sim/pilot` and `@racer/sim/pilot-*` to other packages, so nothing but `stepRace` plans a rider. A `Control` (`packages/sim/src/control.ts`) is the four bytes a control travels in, held as one number: a signed steer byte from -127 to 127, a throttle byte and a brake byte from 0 to 255, and a buttons byte with punch, kick and remount. `controlOf` quantizes a rider's input to that grid, with full lock, a full pedal and zero exact, and the browser runs its own rider on the quantized control, so the player predicts the control the room receives. `readControl` refuses four bytes with a steer byte of -128 or a button bit past remount. The pilot's inputs are not quantized, because they never travel. The pilot's braking envelope and forecast course are in `RaceState.pilot`, because one plan can read entries an earlier plan left there. The buffers a tick fills and reads again are module scratch in the file that uses them: the traffic's lane order in `traffic.ts`, the line chooser's sightings, lane threats, weighed lines and forecast obstructions in `pilot-lines.ts`, the contact parties and strikes in `combat.ts`, and the corner planner's buffers in `pilot-corners.ts`. Each is refilled in place, with a count of the live records, before anything reads it, so it carries nothing from one tick or one race to the next, and a tick allocates almost nothing. `apps/web/test/pilot-replay.test.ts` replays eleven races, nine top-tier quick races, a stress race and one with handovers, to their own outcomes, alone, interleaved, and restored from a snapshot into a fresh state every 600 ticks, against hashes whose outcomes were checked tick for tick against the hashes recorded before the change.

The browser holds a race through `RaceRun` (`race-run.ts`): a readonly `RaceView` of the race itself, its step, and the four commands in `commands.ts` that the dev ride's `?at`, `?kmh`, `?hazard` and `?clear` use to place the player and move traffic. Nothing in `apps/web` writes race state directly. The game steps a race with the player's controls in the frame when the player rides it, and with an empty frame in the attract race and under `?autopilot`.

A rider lives in track space: distance along the road `s`, lateral offset `x` in metres, speed, and lateral speed. The bike is not a rigid body. The model is the smallest one that produces the behaviour we want, and it steers the way the Road Rash games did:

- **The bars take time.** Holding left or right ramps the bike's sideways speed toward full lock at the bike's `steerRate`, about 8 m/s² on the starter bike, so the bike reaches its full sideways speed of 5 to 7 m/s most of a second after the key goes down, a lane change takes a second and a quarter, and the bike keeps moving sideways after the key lifts. `sidewaysRate` in `state.ts` picks the rate: the bike's `steerRate` building toward lock, twice that (`SETTLE_SHARE`) settling back or reversing, and half of it (`BEND_HOLD_SHARE`) while a lifted key still leaves the bars holding against a bend's push, so a tap off the key in a bend does not throw the bike wide. The bars themselves also take time to turn: a control carries the rider's steer target, full lock either way for a key or the stick's own value for a pad, and `applyControl` in `control.ts` moves `input.steer` toward it at `STEER_ATTACK` (9 per second, so a key reaches full lock in 111 ms) and back to centre at `STEER_RELEASE` (18 per second). The ramp runs inside `stepRace`, so the room and every client step the same steer from the same target, and a remote rider's last control is the right guess until their next key edge. A stick that moves no faster than the ramp passes through unchanged. Until November 10, 2026 the browser ramped the steer itself and sent the ramped value, so a remote keyboard rider's control changed for four to seven ticks after every key edge and each tick of it was a wrong guess, a rollback and a visible rival swerve. The pilot writes its steer directly, because nothing predicts it. The lean is only a visual tilt that follows the lateral motion, and it fades from 20% of the bike's `visualLean` at a standstill to all of it at 120 km/h. `rider.heading` is drawn from where the bike is going: the steering left over after the bend's push, never pointing outside the bend, so a bike holding its line through a corner points along the road. Steering authority fades below 12 m/s, but a bike under throttle steers as if it were doing at least 3 m/s, so a rider held at a standstill can still steer out.
- **The throttle and the brake take a quarter of a second.** `RiderState.throttle` and `RiderState.brake` follow the input at 4 per second, so a tap costs little, the needle sits still for the first fifth of a second of braking, and a standing start gathers itself before it pulls. The brakes are strong: the starter bike stops from its 190 km/h top speed 2.3 s after the key, in under 70 m, and from 200 km/h in about 55 m on the Sesta. Off the throttle the engine braking is mild, 1.5 m/s² on the starter bike at the top of its revs and less as they fall, so a bike that has shut off keeps three quarters of its speed after three seconds and about half after seven: a rider who lifts for a bend is not punished the way the old coast-down punished them.
- **Gentle curves carry you, real bends push you out, and leaning scrubs speed.** A bend drifts the bike outward at `curvature · speed² / curvePush`, so riding one with the bars still moves the bike `turn in radians × speed / curvePush` across the road. Centred bars settle into that push only as far as a curve that reads as straight: `settledLean` in `state.ts` is the push of the bend's curvature clamped to `GENTLE_CURVATURE`, 5e-4 per metre, a radius of 2 km, the same 0.05 radians per 100 m the road tests call a straight. Full lock either way still reaches the bike's whole sideways speed, so the steer input spreads the bars from the settled lean out to each lock (`lateralFor`). The band is measured on the road, not as a share of lock, so slowing down does not change which bends need the bars: a rider with the bars centred who brakes into a 200 m bend at 80 km/h still runs wide. Above the band a bend pushes a centred rider by the rest, at every speed. On the Madrid hook's lake road, staged at 190 km/h in its 377 m bend, centred bars run a Sesta 2.4 m from its line and a Wren 2.1 m, where a rider who reacts in a quarter of a second holds it to 1.6 m in three key presses and stays on the road; on the gentle end of that road, under the band, the bike follows. Because full lock is unchanged, every bend has the same speed above which full steer cannot hold it, a rider swerving either way in a bend has the reach they had before, and the pilot's corner speeds still come from `curvePushOf`. The pilot and the dev ride turn the sideways speed they want into a steer with `steerFor`, the inverse of `lateralFor`. From October 24 to November 2, 2026 the settled lean was the push up to 40% of lock (PR #58), which answered a rider losing the bike on the hook but made every bend gentle once the rider slowed: with the pilot's pedals and the bars held centred a rider stayed on the road through 103 of 104 bends on the seven courses and finished six of them. `pnpm check:handling` (`tools/handling`) holds that count down. Leaning costs forward speed: every second the bike loses `leanScrub × lock² × speed`, where `lock` is the share of its sideways speed the bike is using, with the throttle held or not. The square means a gentle sweeper at a quarter lock costs almost nothing and full lock costs the most: on the Wren at 190 km/h that is 10.6 m/s², about 38 km/h a second. That is the bike slowing itself in a bend. A Wren that turns in and holds the throttle through a 140 m bend arrives at 190 km/h and comes out in the 140s, on the road, and it scrubs its way round a 70 m right angle too, down to about 105 km/h. A Sesta holding the throttle into that right angle runs out of road unless the rider lifts or brakes. The play test of October 15, 2026 found that bikes kept their full speed in bends, so the push ran every corner wide and the player braked for nearly all of them. Before that the cost was a flat 0.3 m/s² per metre per second of sideways speed, about 1.5 m/s² at full lock, and every `curvePush` was 77% of what it is now, fitted to a lineup 20% slower; the push grows with the square of the speed, so the faster lineup had been pushed 44% harder at its top speed. Grip is one circle shared by turning, braking and driving. The cornering load is the share of the bike's braking its sideways speed uses, and `brakeGrip` leaves the brakes `sqrt(1 - share²)` of their bite; at 150 km/h at full lock the Sesta brakes at 19.9 m/s², the Anvil at 23.2 and the Wren at 13.0. `driveGrip` does the same for the throttle against the bend's push and the bike's full lock, so a rider who holds the throttle at the limit of a bend stops gaining speed instead of sliding out. The owner set these on November 2, 2026, after a recording of their rides showed the throttle at the apex and key taps were what ran the bike wide.
- **Grass is slow.** Off the road the bike has heavy drag, 45% of its braking, and 80% of its steering authority, and full throttle on grass settles at about 50 mph on the starter bike. Braking and steering fade to the grass values over the first 0.75 m past the edge, so running wide is a slope, not a wall. A hit stuns steering to 65% for a sixth of a second, so a rider punched onto the grass can still fight back to the road.
- **The engine has gears.** `engine.ts` owns the drive. A `BikeSpec` lists the road speed at each gear's redline in `gears`, and `powerPerMass` is the bike's peak pull. Torque over the rev range is a hump that peaks at 72% of the redline and falls to 45% at idle and to 72% at the redline, and thrust is `throttle × powerPerMass × torque(revs) / (redline speed of the gear × the peak of revs × torque)`, so in every gear the bike pulls hardest in the middle of the band and tails off toward the redline. The box shifts itself: up at 96% of the redline, with an 8 tick cut in which the bike pulls nothing and the revs drop into the next gear's band, and down below 58%; in first the clutch holds the revs at half or more while the throttle is open, and over the redline the limiter cuts the thrust. `launchAcceleration` still caps the pull off the line through the tyre load. `RiderState` exposes `gear`, `revs` (0 to 1.05 of the redline), and `shiftTicks`, which the engine note and the dial read. The Halden Wren 400 reads 27, 58, 83, 109, 126, 139, 151, 159, 167, 174, 178, and 181 km/h at 1 to 12 s of throttle from a standstill, reaches 100 km/h at 3.6 s, shifts at 79, 109, 135, 157, and 178 km/h, and tops out at 190 km/h seated and 198 tucked in. Off the throttle from 179 km/h it reads 162, 147, 134, 122, 112, 103, and 95 at 1 to 7 s. The other eight bikes run from the Gutter Pup (145 km/h, 100 km/h in 7.1 s) to the Nera 1000 (283 km/h, 100 km/h in 2.6 s); the table is in `docs/design/game-design.md`. Before October 14, 2026 the Wren was fitted to the original game's measured starter bike (158 km/h, 60 mph in 6.2 s); the user found that slow, and the lineup now reads like modern road bikes.
- **The rider tucks in.** The tuck is a settling-in, not a reflex. `RiderState.tuckTicks` counts the ticks the rider has held the throttle past 0.8 with no brake, less than 0.3 of steering lock, above 120 km/h, on the road, not swinging and not stunned; at 90 ticks (1.5 s) the rider is settled and `RiderState.tuck` eases toward 1 at 1 per second, so the full tuck is in about 2.5 s after the speed is reached. Once settled the rider stays settled through steering and through a lifted throttle: only a brake past 0.5, a strike, a hit, a crash, leaving the road, or dropping below 95 km/h resets the count and drops the tuck at 5 per second. A steering tucked rider stays tucked but rises a little: the target is `1 − 0.25 × lock`, so at full lock the tuck is 0.75 and comes back to 1 at the same 1 per second when the bars straighten. A full tuck cuts drag by 14%, which lifts top speed by about 4% on every bike; at full lock the cut is 10.5%, so a rider holding a long sweeper tucked is still faster than one sitting up, by a little less. Before October 15, 2026 the tuck came in at 72 km/h after 0.6 s and any steering over 0.3 sat the rider up at once; the play test read that as the rider standing up every time they turned. The renderer blends the rider toward a tucked pose by the same number, and combines it with the lean (see "Browser client").
- **Hills matter.** Grade speeds you up or slows you down. Vertical curvature changes the load on the tyres, so a crest goes light, and above about 170 km/h the big crest launches the bike.
- **Trucks throw the bike, and every landing is judged.** A jump comes from a moving double-deck car carrier that tows a ramp (see "Tracks"). The truck is one `TrafficCar` with `carrier: true` in `carrier.ts`. Its traffic box covers the whole rig, so it follows, stops at lights and shows on the pilot's line choice like any car. Only the body, 16.4 m long and 4.22 m high, is solid in a crash; `solidBoxOf` gives that box. The ramp is straight, 10.7 m long, 2.4 m wide, and rises 4.3 m. A rider who rolls onto it from behind rides up it and leaves the lip 4.3 m above the road. The climb off the lip is the rider's speed over the truck's times the ramp's slope, capped at 6 m/s, plus the road's own rise or fall. So the jump depends on speed relative to the truck. The truck drives at 20 m/s (72 km/h), and a rider needs about 125 km/h to clear both decks. A slower rider comes down on the truck and crashes. A rider who hits the rig's back beside the ramp hits the body, and one who steers off the side of the ramp falls from where it was. A rider in the next lane passes on the road without leaving the ground. Road crests also launch the bike: past the crest's takeoff speed the bike flies with the road's own slope. A landing from a truck or a crest is judged the same way: a downward impact against the surface harder than 11 m/s crashes the rider, and after a flight of 15 ticks or more, a quarter of a second, so does landing off the road or with sideways speed above 0.6 of the bike's steering limit. Any other landing costs 0.8% of the speed per m/s of impact, at most 8.8% short of a crash, and starts a wobble that grows with the impact and the sideways speed, sways the bike up to 0.8 m/s across the road, cuts its steering grip by up to 40%, and is gone within 0.9 s. A truck launch on flat road comes down at about 11 m/s, just inside the limit, so a landing where the road rises away from the launch's slope can be a crash.
- **Hazards lie on the road.** An oil slick, a rock, or a pothole is an entry in `RaceState.hazards` (see "Hazards as race state" below). Hazards are good to avoid, not must avoid: none is a crash on contact, and what one costs depends on speed and lean. A bike touches one when its footprint, moved along the straight path it takes in the tick, overlaps the hazard's on the ground; on the tick a bike lands, only the path after touchdown counts. Every hazard touched in a tick acts, in the order the path meets them, until one puts the bike in the air or on the ground. A bike in the air passes over, and a hazard the bike was already touching on the previous tick does not act again, though oil keeps the grip down for as long as the bike is on it. Oil takes 85% of the grip, and the share comes back at 1 per second once the bike is off the slick: the bars turn the bike's sideways speed toward the rider's input at the grip's share of the steer rate, the brakes keep 1 − 0.7 × the lost share and the drive 1 − 0.6 × it, and a bend pushes up to twice as hard, so a bike that was moving sideways keeps moving sideways and a bike in a bend slides wide. A short wobble sets in. Riding straight across at a steady line costs a few per cent of the speed and nothing else; holding 0.8 of the steer or more for 18 ticks (0.3 s) while more than half the grip is gone above 26 m/s (94 km/h) puts the rider down, a `hazard` crash that names the slick. Half the grip is back 0.35 s after the bike leaves the slick, so a quick tap of the bars on the slick or just past it is safe and only a held turn is not. A rock is a small road rock, 0.6 m across and 0.3 m high. Hit square above 14 m/s (50 km/h) it bumps the bike into the air: the bike leaves the road at 7% of its speed upwards on top of the road's own rise or fall, as a truck launch does, so a rock on a climb throws it as high as one on the flat, loses 6% of its speed plus up to 10% more at 200 km/h, and is knocked sideways, the way it was already moving, by half its steering limit times the cube of its speed over 55.6 m/s (200 km/h). The landing rules for a jump then decide. Straight over at 130 to 180 km/h the bike is in the air for 0.5 to 0.75 s, lands wobbling, and rides on; from about 210 km/h it lands too far sideways and the rider is thrown; a bike steering at 0.7 of its limit or more is thrown from about 60 km/h, at half its limit from about 120 km/h. That landing crash is a `hazard` crash that names the rock. Slower than 14 m/s, or when the bike only clips the rock's edge by less than 0.2 m, it is a stagger: the bike keeps 40% of its speed (80% when clipping), is put beside the rock and pushed off it at 2.5 m/s, wobbles hard, and the rider flinches for ten ticks. A pothole is a jolt that costs 3% of the speed plus up to 3% more at 216 km/h, and a wobble of 0.3 that grows with how hard the bike is leaned and how fast it is going and is gone within a second; only a bike leaned past 85% of its steering limit above 48.6 m/s (175 km/h) is thrown, so a pothole ridden straight at any speed costs speed and a jolt and nothing more. A hazard crash costs the bike the same condition as a knockdown, 28 at 200 km/h. Passing within 0.8 m of a hazard's side above 20 m/s is a `nearMiss`.
- **Crashes separate rider and bike, and wear the bike out.** A hard hit throws the rider, who flies, bounces, slides, lies still for half a second, gets up, and is then on foot until they press remount, run to the bike, lift it, and climb on (`thrown`, `lying`, `running`, `mounting`). The body keeps 60% of a share of the bike's speed that depends on the cause (half of it into a pole, 65% when knocked off) and loses 10 m/s² on the ground, so the fall is a function of speed: a rider thrown into a pole at 160 km/h travels 28 m and is on their feet 3.2 s after the impact; a knockdown at 100 km/h has the rider on their feet at 2.8 s; at 50 km/h at 2.1 s; and a tip-over at walking pace at 1.6 s. At 200 km/h the body travels 40 to 70 m whatever the cause, against 107 to 209 m before November 3, 2026, when a play test found riders flung too far forward. While the rider tumbles the steer moves the body sideways at up to 5 m/s and the brake takes up to 10 m/s² more off the slide. The tumble reads those two controls directly, not through the stale marks below, so a key held through the crash works at once. The bike stays where it fell. It slides on its side at 10 m/s², keeping 60% of its speed when the rider is knocked off, so after a fast knockdown it ends up nearer the body than the bike that stopped against a pole.

**On foot the rider is steered, not scripted.** In the `running` mode the rider's input moves the body: throttle runs up the road, brake runs back down it, and steer runs across it, so the controls mean the same thing they mean on the bike and the camera, which keeps facing along the road, never has to turn. The run tops out at 7 m/s in any direction (a diagonal is scaled so it is no faster), reaches that in a quarter of a second, and stops as fast. A control that was held when the rider went down does nothing on foot until it has been released: `throwRider` marks the throttle, the brake, and the steer as stale, and each clears on the first tick after the fall on which that control reads zero, so a player still holding the throttle from the ride does not walk the rider away from the bike and out of frame, and a fresh press moves them. A rider who touches nothing stands where they got up and can be arrested there. The first 18 ticks of `running` are the rise from the ground and take no input. The body is held inside the verges and between the start and the finish line; a rider cannot finish on foot. Touching the bike does nothing. One press of remount (E, or the pad's first face button) at any moment from the throw onwards sets `RiderState.runningToBike`, and from then on the rider ignores the other controls and, once up, runs straight to the bike at the run speed. Within 0.7 m of the bike they start `mounting`, which takes half a second before the bike moves. Traffic can still knock them down on the way, and they carry on to the bike afterwards without a second press. The prompt on the HUD shows while the rider is off the bike and has not pressed it. The pilot holds the same button for every rider it plans who is off the bike, so rivals and police get back on by this one path; in multiplayer a remote player's press is a bit in the same four-byte control as their riding. With the run at 7 m/s a knockdown at 50 km/h is back on the bike 3.5 s after the fall if the rider presses remount at once, one at 100 km/h 4.3 s, and the walk after a 200 km/h crash takes the whole fall to 5.3 to 9.9 s. A rider on foot can be knocked down again: a car or a bike moving faster than walking pace that reaches the body puts the rider back into the tumble, carrying a quarter of the vehicle's speed, and they are on their feet again about two seconds later. That is a `knockedDown` event, not a `crash`: the bike is not involved, so it costs no condition and counts as no crash, though a bike that does it is remembered as the last rider to hit them. A bike that runs over a body loses a tenth of its speed and bumps. Each crash also takes condition off the bike, which starts at 100. At 200 km/h that is 34 for traffic, 32 for a tree or pole, 30 for a hard landing or for running into another rider, 28 for a knockdown or a hazard, and 22 for leaving the track. The cost scales with the speed at impact over 200 km/h, held between a tenth and one and a quarter, so a crash at 100 km/h costs about 15 and a tip-over at walking pace about 3. At zero the bike is wrecked: the rider and bike slide to a stop as in any crash, are then moved onto the verge where traffic ignores them, and that rider's race is over with no fine. Three crashes into traffic at 200 km/h wreck a bike, and so do four knockdowns at that speed. Police bikes and riders who have already finished take no damage. A light side contact with a car only costs speed. A gentle bump into the nose of a car that is stopped or coming the other way leaves the bike up to 3 m/s and slides it sideways round the bumper at 3 m/s, towards the side the rider is steering or else the nearer side, so the bike and the car never hold each other still.

`BikeSpec` holds the numbers for one bike: power, drag, brakes, lateral speed, steer rate, curve push, lean scrub, and visual lean, with its class and price. Each rider carries their own (`RiderState.bike`), so the riding step, the pilot's corner speeds, and the lean the renderer draws all come from the bike that rider is on. `bikes.ts` builds the nine bikes of the catalogue in `docs/design/game-design.md` from the `spec` of each row in `packages/content/src/bikes.ts`, keyed by id. The Halden Wren 400 is the bike the numbers were measured on, against the original's starter bike. The Ostra Sesta 600 is exported as `streetBike` and is the bike the default race and most of the tests ride; its `curvePush` of 2.43 and `steerRate` of 6.25 stand in the same ratio to the Wren's 2.79 and 8.1 as before the retune, as does every other bike, and its `leanScrub` of 0.17 sits between the Wren's 0.2 and the Anvil's 0.14, so a heavy bike leaned over keeps more of its speed and needs the brake where a light one only needs to lean. Faster bikes are new specs, not new code.

`pilotRider` in `pilot.ts` is the AI rider, and `stepRace` runs it for every rider whose controller is `pilot`. It corners from the same physics the player's bike obeys. For every point of the road within its braking reach it takes the hold speed, the speed at which the bend's push there equals the bike's whole sideways speed, so full lock just holds the line, and aims for a share of it set by skill: 0.99 less 0.3 times its lack of skill, so 0.93 for a rider of skill 0.8 and 0.987 for one of 0.99. Oil on its chosen line adds a point at the slick, at the speed the slick allows (below). From those points it works backwards along the road, 5 m at a time, to the fastest speed it may carry at each point and still make every point ahead. Each step allows 90% of the brakes, weakened by the lean the bend there needs at that speed and by tyres gone light over a crest, plus drag, engine braking, and lean scrub at that speed and lean, less the pull of a downhill or plus that of a climb. A natural crest is planned this way. At every point where the road's drop would put the bike in the air at the speed the envelope allows there, by the same rule the bike leaves the road by, the pilot follows the flight from that point's height and slope until it meets the road, and lets the bike fly only at a speed that lands on the road, under the landing slip, and no faster than the road after the landing allows; otherwise it holds the speed at which the bike stays on the ground there. At the top of a 15 m climb that turns straight into a 60° bend, a skill-1 Sesta takes off at 162 km/h instead of 187 and lands on its line instead of running off the road. It rides that envelope smoothly. The throttle closes over the last 0.25 m/s below it. The brake comes on when the bike reaches the envelope 0.15 s ahead, the time the brake takes to bite, asks for the deceleration the envelope asks there plus 4 m/s² for every m/s over, and stays on, easing, while the envelope still falls, so in a steady bend the throttle holds the speed and the brake does not flicker. A bend that asks for less than 5% off its speed, and that a closed throttle alone can make, gets a lift and no brake. The pilot brakes hard only in an emergency, when the bend is carrying it outward faster than full steering can stop before the road edge. It steers ahead of a tightening bend. The bars change the bike's sideways speed only at the steer rate, so it sets its sideways speed now so that it can still reach the push of each coming point, at the speed it plans to have there and no more than the bike's limit. It settles onto its line by how far the bike is drifting across the road, the sideways speed less the bend's push, not by the sideways speed alone. Together these hold the bike within 0.5 m of its lane line through Hermit's Bend and the sweeper after it. While it moves toward the inside of a bend it plans that bend on the sideways speed left over: the sideways speed the move asks for, as a share of the bike's limit up to 30%, comes off the grip for the next 0.83 s of road. The line chooser's forecast rides each candidate at the speed the pilot will have there, from the envelope and that line's own hazard speeds, takes the push where the bike will be at that speed, and after oil steers with the slick's grip, so it does not plan a pass a leaned bike cannot make or a line across oil it cannot hold. For every drop ahead it lifts, planning 3.5 m/s², to stay under 1.15 times the speed at which the bike would leave the road, times its skill, so a heavy bike arrives at the Saddle at about 190 km/h and lands instead of crashing. Before October 16, 2026 the pilot aimed for the speed at which the push took 80% of the sideways speed, times its skill, and planned 6.5 m/s² of braking, a quarter of what the brakes give, so it took bends at 71% to 90% of the hold speed and began braking 65 to 85 m before it had to; a play test said the riders braked far too soon. The first late-braking pilot, later the same day, counted metres in the air as braking room, ignored the grade, held a bend by switching between brake and throttle, and let the bike drift up to a metre wide of its line; the envelope replaced it. It picks a lane around traffic and other riders, and throws punches and kicks at a rate set by its profile's aggression, after a truce of 7 s from the start so the pack sorts itself before the fists come out. A rival is paced by its gap to the player, rider 0, with the two numbers in `RaceState.pacing`: ahead of the player its throttle is capped so it holds no more than `topSpeed × (1 − leadEase × share)`, where `share` is the gap over 200 m clamped to 1, and it never brakes for pace; behind the player its corner share rises by `catchUp × share`, never above 0.99, and the share of the brakes it plans on rises by the same, never above 98%, so it carries more speed into bends and brakes later; it never exceeds its bike's top speed. A rider already near the cap has little to gain: over 60 s of Ridge Road at a `catchUp` of 0.1 a rival of skill 0.8 gains 26 m and one of skill 0.93 about 6 m. The player, the police, busted and wrecked riders, and everyone once the player has finished, been busted, or been wrecked ride unpaced. `topSpeedOf(bike, tucked)` in `engine.ts` is the speed in top gear where the bike's thrust meets its drag and rolling loss, seated or tucked. It steers for where the bars will have taken it, aiming short of its lane by the distance its drift across the road still needs to ramp down, and it holds speed with a part throttle of about 0.6 that falls to nothing 0.75 m/s over its target; 1.5 m/s over, the brake takes over. A cop riding to the spot beside its quarry checks every lane it will cross for a car, not only the lane it is heading for; a same-way car beyond a downed rider's body does not count, because the cop stops at the body, but an oncoming car beyond it does, because it comes through. Its home is the same-way lane next to the centre line, and it goes back there whenever that lane is clear. When something blocks it, it takes the first clear lane in order of preference: the other same-way lane, then the oncoming lanes, so on a road with two lanes each way a rival behind a slow car passes in the outer lane and only crosses the centre line when both same-way lanes are blocked. A rider or a body overlapping the pilot along the road, within 2 m ahead or 4 m behind, blocks the lane it is in whatever its speed, so the pilot never steers into a bike alongside and a grid gets away in its own lanes instead of everyone converging on the home lane and leaning on each other. A lane it would have to cross to get there must not hold a threat due within 1.5 s, unless the bike is already in that lane, within 1 m of its centre; a bike beside a car does not steer through it to reach a clear lane on the far side. An oncoming lane takes more clearance to enter than to stay in: the pilot enters one only when the nearest oncoming car is more than 8 s of closing away, 12 s in the first 10 s of a race, and leaves one it is in when a car comes within 4.5 s, so a rider does not commit to the wrong side of the road and find the pack has closed the way back. When no clear lane can be reached it splits the seam between the lane it is in and the neighbouring lane, the same-way one if there is a choice, at the blocker's speed plus 8 m/s; a seam that straddles the centre line sits 0.6 m on the same-way side of it, which clears a truck's overhang. On a road with one lane each way nothing else is ever between two lanes: its own lane, then the oncoming lane, then the near side of the centre line. It judges a swing by the reach of the weapon in its hand and a kick by the reach of the boot, so a chain holder attacks from further across than a rider with fists. An unarmed rider next to an armed one prefers to kick. A rival can hold a grudge against one rider: when that rider is in reach the pilot goes for them instead of anyone nearer, on their side. A rival can also carry an `aggressionBoost` toward the player, rider 0. The pilot adds it to the rival's aggression whenever the rider it would strike is the player, with or without a grudge, so a boost above zero means more attacks on the player and one below zero means fewer. Toward everyone else the rival keeps its profile's aggression. The pilot rides round downed riders and ignores wrecked ones. The same code drives the attract race, the rivals, the police, and the player under `?autopilot`. Its dice live in `RaceState`, so a race replays the same way whatever ran before it.

The pilot treats a hazard as a cost, not a wall, and chooses its line once, with hazards and traffic in the same scoring. It sees hazards 2.35 s plus 15 m ahead. While one is in sight, the candidates are the lanes, the lines just clear of either side of every hazard in sight (the hazard's half width, the bike's, and 0.45 m), the lines 0.3 m clear of either side of every car it is catching within sight, the line it chose last tick, following whatever blocks its own lane at that thing's speed when it can brake to that in time at 6.5 m/s², and for a cop the spot beside its quarry. A line is out when it is off the road (0.2 m inside the edge) or fails the lane tests above: traffic or a rider on the line, or a threat due within 1.5 s in a lane the move crosses. Every line left gets one score: its lane rank (1 per lane down the order of preference, 0.2 more between lanes, 5 more for following, -1 for a cop's pursuit spot), 0.05 per metre across, and a toll for what the move runs into. The toll comes from running the pilot's own steering tick by tick toward the line for up to 3.5 s, at the speed the forecast above gives: every hazard the bike would touch on the way, within the two half widths plus 0.1 m, costs 0.6 for a pothole, 1 for oil, and 2 plus 2 × (speed / 200 km/h)² for a rock, and every car it would reach while beside it costs 10, except the one a following line brakes for. A car is reached where the forecast's own distance travelled meets the car's position at that moment, so a line that slows for a rock or a slick meets an oncoming car where the slower bike would meet it, not where the bike at its present speed would. A rock is also checked for the landing: the pilot takes the speed at which the bike, with the sideways speed the forecast gives it there plus the bend's push, and the rock's upset, would land under 85% of the slip that throws a rider, and rides the line at that speed; when braking at 6.5 m/s² cannot get it there before the rock, the line costs 10 more, as a crash. Oil is checked the same way for the slide: on a slick a bend pushes nearly twice as hard while the bars barely turn the bike, so the pilot takes the sharpest curvature from the slick's near edge to 0.6 s past it and rides a line that crosses the slick no faster than the speed at which that bend pushes the bike sideways at 1.2 m/s (across a turn-in slick on a 60° bend that is 76 km/h, and the bike slides 1.5 m instead of 3.2 m at the 139 km/h corner speed); when the bike's whole braking at its present lean, allowing 0.15 s for the brake to bite, cannot get it there before the slick, the line costs 10 more. That speed goes into the braking envelope as a point at the slick and holds to 0.6 s past it, so the pilot brakes for oil as late as for a bend, from the same deceleration. Oil on a straight costs no speed. So a pilot rides round turn-in oil when a lane is free and otherwise brakes before it and crosses it upright, and one squeezed onto the edge of a slick by a car or a rival can still slide into it. The line chosen last tick gets 0.15 off, so the pilot keeps a line until a better one is worth more than that or it stops being open, and does not flip sides in the middle of a move. A bump beats a truck: when the only open lines cross a hazard the pilot takes the hazard, and on a line that touches a rock it eases to 150 km/h or the landing speed, whichever is lower. When no line is open it splits the seam as above. While the bike is losing grip it never steers past 0.45, so it does not put itself down on oil. An unskilled rider sometimes does not see a hazard: the chance is 0.4 times its lack of skill, rolled once for the nearest hazard in sight from `RaceState.hazardDice`, a stream seeded for hazards alone so that hazards do not shift the dice for jumps and fights. Cops use the same chooser, so a cop rides round a hazard in a chase, and a hazard spawned during the race is seen exactly like one on the schedule.

The pilot jumps trucks when it can. `jumpAim` in `pilot-jumps.ts` judges a truck once, when the pilot is within 1.7 m of the truck's lane and 3 s from the ramp's toe at its closing speed. The jump works if the closing speed clears the decks, a forecast flight over the road's real heights lands under the hard-landing limit, the landing is on the road and leaves room to brake for the next bend, no car is between the pilot and the toe, and no car will be in the lane from 15 m before the landing to one second of riding after it at the moment the pilot comes down. All of these read the truck's numbers from `carrier.ts`. An unskilled rider sometimes misjudges: the chance is 0.8 times its lack of skill, rolled once per truck from the race's dice, and it then commits whether the jump works or not. A committed pilot aims at the truck's line and drops that truck from its traffic and forecast scans, so the rig's own box neither brakes it nor pushes it off the line. A pilot that does not commit goes round the way it does for any car; if its line would clip the rig, it moves to one 0.15 m clear of the truck's side. Before a crest that would launch it, within 0.6 s, the pilot straightens up, aiming to let its sideways speed run out, so it lands square.

Combat lives in `combat.ts`. A punch or kick lands on the nearest rider on the chosen side within about two metres, drains stamina, shoves them sideways, and stuns their steering briefly. The timings are tuned for snap, not for the original, whose measured 0.2 s wind-up the first play test called slow, and were shortened again on October 15, 2026 when the second play test still called them sluggish: a punch is fully out 4 ticks (0.07 s) after the press and the swing is over at 18 (0.30 s). The third play test, on October 15, asked for a quicker kick that rises off the seat first, the way the original's did: a kick lands 4 ticks (0.07 s) after the press and its swing is over at 15 (0.25 s), against 5 and 20 before. Its cooldown stays at 36, so a held kick key lands one kick every 0.6 s as before and fights last as long. A strike's `cooldown` is the shortest time from one press to the next. For fists it is 16 ticks, two short of the swing, so a press in the last two ticks of the follow-through starts the next punch at once with no return to neutral, and a held key lands a punch every 16 ticks and never faster; that is the old damage rate within a tenth, so the quicker arm does not shorten a fight. A kick cannot be chained into a follow-through, and a weapon with no hits left breaks when the chained swing starts. Every weapon's cooldown is longer than its swing, so a weapon always returns to neutral between swings. The renderer does not ease into a strike pose; it reads the swing's clock. `strikeFrame` in `rider-fight.ts` turns `attackTicks`, plus the frame's fraction of a tick, into a `reach` of 0 to 1: the arm or leg extends linearly over the wind-up so it is fully out on the tick the hit lands, holds for 4 ticks, and comes back over 5, so a punch is out at 4, held to 8, and seated by 13, and the 3 ticks of neutral before the 16-tick cooldown make mashing read as jabs. A kick has its own clock with two numbers: a `rise` off the seat and the leg's `reach`. The rise eases out over the first 2.5 ticks, so the rider is two thirds of the way up after one tick; the leg snaps out over the last 1.5 ticks before the hit, holds 2, and pulls in over 3; from tick 8 the rider drops back onto the seat, accelerating, and is seated at 13, two ticks before the swing ends. A kick from a tucked rider rises out of the tuck. Weapon swings and punches stay seated: the swing poses are whole-body poses authored seated, the stop sign's wind-up would hold a standing rider for half a second, and the original threw its swings from the seat. A weapon swing winds up into the windup pose over 3 ticks, holds it until 3 ticks before the hit, and then swings through to the strike pose on the landing tick, so the stop sign's 27-tick wind-up is 21 ticks of a visibly raised sign. The struck rider flinches: the renderer rolls the torso and head away from the hit by `hitStun`, which is 10 on the landing tick and falls to 0, so the reaction is instant and over in a sixth of a second. A rider whose stamina reaches zero is thrown. Strikes that come due on the same tick are all aimed before any of them lands, so two riders who swing at each other both connect. Cooldown and stun timers tick down before any strike lands, and every strike lands before any rider starts a new swing, so both are stunned for the same ten ticks and nobody starts a swing on the tick they were hit. Every rider remembers who last hit or touched them and when. A `crash` event carries `by`: that rider if it was within the last 60 ticks, otherwise −1, so a rider punched into a car is put down to the puncher. Rider-to-rider contact is sorted by where the two bikes were a tick earlier. If they were clear of each other along the road and already overlapping across it, the one behind ran in: a rear-end. Above a closing speed of 18 m/s it throws the rider behind, once per tick at most, and leaves them behind the bike they hit. Below that it is a bump that bleeds the speed forward: the rider behind drops to the speed of the bike ahead, less 0.5 m/s, and is held behind it, and the bike ahead is shunted on by 30% of the closing speed, up to 5.4 m/s, so a player who holds the throttle into the back of a slower bike is slowed to its pace rather than thrown. Before October 14, 2026 the line was 9 m/s, and a player who held the throttle off the grid was thrown into the pack in most starts. If they were clear across the road and overlapping along it, it is a side shove that pushes both bikes apart. If both gaps closed in the same tick, the one that closed last decides. A side shove costs each rider 0.9 m/s on a tick however many bikes touch them, and no more than 6 m/s in any second, so two bikes leaning on each other cannot hold each other still. The condition it costs and the speed on its `crash` event come from the speed the rider had at impact, not from the bike they ran into. Every pair in contact is read from the positions and speeds the riders had when the contact step began, and the pushes are added up before any is applied, so a three-bike pileup comes out the same whichever rider is listed first. A rider who runs hard into two bikes at once is thrown off the nearer one, and both of them are shunted forward. Traffic cars follow each other from the previous tick's positions. Each lane is its own sorted queue: a car follows the car ahead in its lane, never changes lane, and yields to a rider or a body in its lane. A car matches the car ahead once the gap falls under the longer of its following distance, 10 m plus 0.9 s of its speed, and the room it needs to brake down to that car's speed at 7 m/s², plus 2 m. The following distance alone is shorter than the stopping distance above about 20 m/s, and until November 2026 a car at cruising speed drove into a car stopped for a walker or a rider: on Breakwater Run about 2 times a race at tier 1 and 7 at tier 3 with one width, and 4 and 13 with its districts. A car that has stopped for a rider on the bike stays stopped until the rider is out of its way; it does not creep forward. A bike or body down in its lane holds a car only for that car's `patience`, 90 to 180 ticks (1.5 to 3 s) rolled per car from a stream seeded for it alone, so the patience dice move nothing else. The car counts `waited` while it is stopped facing them, then pulls away and drives over. Each car that has waited knocks the bike once on its way past: the bike is shoved the way the car is going at 1.4 times the car's speed and at least 5 m/s, sideways away from the car's centre at up to 6 m/s, so a square hit sends it furthest up the road and a hit on one side sends it to the other. A run-over takes 40 off a racer's condition but never below 1, so it cannot wreck a bike on its own and the next crash of any size finishes it. A car that reaches the rider on foot still knocks them down. Remounting restores stamina to 55.

Weapons are numbers in `weapons.ts`, the same way handling is a `BikeSpec`. A rider holding one swings it when they press punch; kick stays a kick. Each strike has damage, shove, reach, timing, and a number of hits before the weapon breaks:

The stop sign is the biggest hit and the slowest to come round again, 50 ticks against the club's 40, and a rider holding it has 85% of their bike's steering response.

`strikeTick` counts the ticks left in the swing when the hit lands, so a strike lands `ticks − strikeTick` ticks after the press. A weapon lands one to three ticks after a fist would, in the order cue, crowbar and baton, club and chain, and follows through for a tick or two longer; the swings and cooldowns are unchanged, so the cadence of an armed rival or a cop is what it was. The stop sign's swing is 44 ticks with a `strikeTick` of 17, so it lands 27 ticks (0.45 s) after the press, which is the shortest wind-up a rider 2 m across can still steer out of, and follows through for 17.

A kick that lands on an armed rider hands the weapon to the kicker if the kicker is unarmed. Who was armed is read when the strikes are aimed, so two riders who kick each other on the same tick end the same way whichever is listed first: the unarmed one takes the weapon and keeps it. A swing that lands on that tick still costs the weapon a hit, and if two unarmed riders kick the same holder the nearer one gets it. A thrown rider drops whatever they hold. Rivals start with the weapon in their profile and a full count of hits. The player starts with the weapon and the hits left that the race setup carries over from the last race.

Police are riders with the `police` role, so riding, contacts, combat, and the renderer treat them like anyone else. How many there are, how fast they chase, how far they see, how far past their post they keep chasing, and what a bust costs come from the race setup. `createRace` parks them on the verge, 1.1 m beyond the road edge, spread over the road's length: the first 1.5 km from the start, the last 1 km before the finish, and the rest evenly between, so a tier's police cover the whole race however long the road is, and a single cop sits at 1.5 km. A parked cop sits still until a racer is alongside it or up to 35 m ahead of it, then pulls out, so the pack meets the first cop about forty seconds into a race, once the pack has sorted itself out, instead of chasing a patrol it may never catch. A cop that has pulled out and has nobody to chase patrols at 22 m/s. `police.ts` decides whom a cop chases: a downed racer whose body is within 60 m ahead comes first, then the nearest racer riding within the sight range, who is kept until they are 120 m away. Each cop remembers its `post`, the spot where it was parked. Once it is more than the setup's `beat` past that spot it chases nobody new, pulls onto the verge, and stays there; a cop riding to a downed racer finishes that first. The pilot rides alongside a riding target at up to the pursuit top speed, which a tier sets below the top speed of the bikes raced there, and swings its baton. It rides to a downed rider's body no faster than that speed either. A chasing cop picks its lane around traffic the way a racer does, at the speed the chase calls for. It leaves that lane for the spot 1.5 m beside its quarry only when it is within 20 m of them and no car threatens that line, and for a downed rider's body only when no car nearer than the body does. A pilot gives a car that drives the other way its longer warning even when that car has stopped. A racer who is off the bike when a riding cop is within 4 m of their body is busted, except in the first 30 ticks after they are thrown: a rider who is running back or lifting the bike can be arrested at once, and one who has just come off cannot, so a cop riding alongside does not arrest a rider on the tick they fall. A cop riding alongside a rider who falls at 160 km/h cannot brake in time, rides past the body, and the rider gets away. A cop that stops within 10 m past its quarry's body makes the arrest from there, which is any cop alongside at up to about 90 km/h. A cop 60 m back at 160 km/h has the room to brake and makes the arrest too; one that is 60 m back when a rider falls at 50 km/h arrives after the remount and gives chase instead. Their race ends with the setup's fine, and standings put busted and wrecked riders after everyone still racing, ordered by how far they got. A thrown rider drops their weapon at once, so each rider keeps `weaponAtThrow`, the weapon they held when they were last thrown. The `busted` event carries the body's `s` and `x` at the moment of the arrest and that weapon, all read before the rider is moved. The busted rider and bike are moved onto the verge and traffic stops braking for them, so a bust never blocks the road. A cop that is off its beat or within 80 m of the end of the track pulls onto the verge for the same reason: it crawls at 6 m/s until the bike is clear of the road edge and only then stops, because a bike that brakes to a halt first has no steering left to leave the lane with. A cop who is knocked down remounts with a fresh baton. Police are not in the standings and cannot finish.

## Hazards as race state

The compiled track only holds the schedule. `createRace` hands the scheduled placements to `spawnScheduledHazards` in `hazards.ts`, which spawns each one whose `rarity` is below the race's `hazardShare` by calling the spawn function for its kind: `spawnOil`, `spawnRock`, or `spawnPothole`, each `(state, track, spot)` where `spot` is `{ id, s, x, command }`. A spawn appends a `Hazard` to `RaceState.hazards` with its id, kind, size, position, the tick it appeared, and `command`, which is null for the schedule. It refuses, returning undefined, a spot that is off the road or reuses an id already in the race, so a hazard id is unique in a race and its index in the list never changes. Riding, the pilot, the cops, and the renderer read only `RaceState.hazards`, never the schedule, so a hazard spawned between ticks is ridden into, avoided, and drawn exactly like one placed by the track. The `crash` event carries `hazard`, the hazard's id, kind, and command, or null for a crash with another cause; a touch that does not crash is a `hazard` event with the effect (`slip`, `stagger`, `bump`, or `jolt`), and a near miss carries the hazard or null for a car. Each rider keeps the indices of the hazards it touched on the last tick in `hazardContacts`, and the rock that bumped it into the air in `bumpedBy` until it lands, so the landing crash can name it. The `land` event carries the touchdown `s` and `x`.

This is the surface the race director builds on. A director command stamped with a tick, applied at the start of `stepRace` as in the lane-change experiment on `feat/race-director-events`, calls `hazardSpawners[kind]` with the command's id as `command`, and every event the hazard causes names that command. `stepRace` takes no director argument yet.
